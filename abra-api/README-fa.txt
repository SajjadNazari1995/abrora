Abra Core API — راهنمای نصب و اجرا (نسخه ۱)
=============================================

این API مستقل از وردپرس است و فقط ciphertext (انبارهٔ رمزشده) و اطلاعات حساب را نگه می‌دارد؛
هیچ داده سلامتی به‌صورت متن ساده به آن نمی‌رسد. قرارداد کامل: abra-docs/API-v1.md

نیازمندی‌ها
-----------
- PHP 8.1 یا بالاتر با افزونه‌های pdo_sqlite یا pdo_mysql، openssl، curl، mbstring (sodium اختیاری)
- MySQL 8 / MariaDB 10.4+ (برای تولید) یا SQLite (توسعه و سایت کوچک)
- HTTPS اجباری در تولید

نصب
---
1) پوشهٔ abra-core را روی سرور بگذارید. فقط پوشهٔ public/ باید از وب در دسترس باشد
   (DocumentRoot یا زیردامنه api.<دامنه> را روی public/ تنظیم کنید).
   اگر هاست اشتراکی است و نمی‌توانید DocumentRoot را عوض کنید: پوشهٔ public را محتوای public_html کنید
   و مسیر require در public/index.php را به src/bootstrap.php اصلاح کنید (src و data بیرون از وب بمانند).
2) cp config.sample.php config.php  و ویرایش:
   - pepper: یک رشتهٔ تصادفی بلند (بعد از راه‌اندازی هرگز عوض نکنید)
   - db.dsn (MySQL یا SQLite)، allowed_origins، google_client_ids، apple_client_ids، app_base_url، mail
   - config.php را خارج از وب نگه دارید (یا با متغیر محیطی ABRA_CONFIG مسیر دیگری بدهید)
3) ساخت جدول‌ها:      php bin/migrate.php
   (با phpMyAdmin هم می‌شود: schema/mysql.sql را import کنید.)
4) توکن مرکز کنترل:    php bin/make-service-token.php control-center stats:read,accounts:read,accounts:status,release:read,release:write,ops:read
   مقدار SECRET را یک بار به مرکز کنترل بدهید؛ خط hash را در config.php زیر service_tokens بگذارید.
   (می‌توانید فهرست IP مجاز هم به‌عنوان آرگومان سوم بدهید.)
5) کرون روزانه:        php bin/cleanup.php
   (نشست‌ها و توکن‌های منقضی، rate limit، خطاهای قدیمی، و ردهای رضایت بی‌هویت‌شده بعد از مدت نگهداری قانونی)
6) ایمیل: پیش‌فرض mail() است. برای SMTP در config.php یک تابع mail.hook بدهید.

اجرای آزمون‌ها
--------------
    python3 tests/run_tests.py
سرور موقت php -S روی 127.0.0.1:8790 با دیتابیس و پیکربندی موقت بالا می‌آید، آزمون‌ها اجرا می‌شود و سرور بسته
و فایل‌های موقت پاک می‌شوند. (پایتون ۳، php و دستور openssl لازم است.)

امنیت — خلاصه
--------------
- فقط prepared statement؛ مقایسهٔ ثابت‌زمان؛ توکن‌ها فقط به‌صورت SHA-256 ذخیره می‌شوند.
- بدنه، رمز، توکن، idToken و blob هرگز لاگ نمی‌شوند. خطاها عمومی‌اند.
- محدودیت نرخ: ورود (۱۰ شکست/۱۵ دقیقه)، ثبت‌نام ۵/ساعت، فراموشی رمز ۵/ساعت، کلی ۳۰۰/دقیقه برای هر IP.
- توکن ادمین هیچ‌وقت به مسیرهای کاربر/vault نمی‌رسد و برعکس.
- حذف حساب: همه‌چیز از جمله vault در یک تراکنش پاک می‌شود؛ فقط رکورد رضایت بی‌هویت (tombstone) می‌ماند.
- پشتیبان‌ها طبق backup_retention_days (پیش‌فرض ۳۵ روز) خودبه‌خود چرخش می‌کنند؛ پاسخ حذف همین را صادقانه می‌گوید.

محدودیت‌های شناخته‌شده
-----------------------
- ورود Google/Apple با کلیدهای زندهٔ ارائه‌دهندگان در این محیط آزموده نشده (آزمون‌ها با JWKS محلی و توکن امضاشدهٔ محلی‌اند).
- اسکیمای MySQL اجرا نشده (در این محیط MySQL نبود)؛ فقط SQLite آزموده شد.
- تأیید ایمیل (email verification) در فاز ۱ نیست؛ حساب‌های ایمیلی emailVerified=false می‌مانند تا بازنشانی رمز.
- محدودیت اندازهٔ vault (۶ مگابایت) به post_max_size / memory_limit / max_allowed_packet در MySQL هم وابسته است؛
  حداقل: memory_limit=128M، max_allowed_packet=16M.
- rate limit با جدول دیتابیس است؛ برای ترافیک خیلی بالا بهتر است جلوی آن CDN/WAF هم باشد.
